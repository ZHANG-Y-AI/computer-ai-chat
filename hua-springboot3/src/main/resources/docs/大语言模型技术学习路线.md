# 大语言模型技术学习路线

## 1. 文档定位

本文档面向希望系统学习大语言模型技术的同学或团队成员，适合用于课程演示、知识库导入和后续学习规划。路线以“从基础认知到项目落地”为主线，帮助学习者逐步理解大语言模型的核心概念、关键技术、工程实践和应用方向。

学习目标包括：

- 了解大语言模型的发展背景、能力边界和典型应用场景。
- 掌握自然语言处理、深度学习和 Transformer 架构的基础知识。
- 理解预训练、指令微调、提示词工程、RAG 和智能体等关键技术。
- 能够使用现有大模型 API 或开源模型完成一个可演示的应用项目。
- 建立持续学习和技术跟踪能力。

---

## 2. 阶段一：基础认知入门

### 2.1 学习重点

本阶段的目标是建立对大语言模型的整体认识，不急于深入算法细节，重点理解“大语言模型是什么、能做什么、不能做什么”。

需要掌握的内容：

- 人工智能、机器学习、深度学习之间的关系。
- 自然语言处理的基本任务：分词、文本分类、机器翻译、问答、摘要、信息抽取等。
- 大语言模型的基本概念：参数、上下文窗口、Token、生成式模型、多模态模型。
- 常见模型与产品：GPT、Claude、Gemini、LLaMA、Qwen、DeepSeek、ChatGLM 等。
- 大语言模型的典型能力：文本生成、代码生成、知识问答、逻辑推理、文档总结、辅助编程。
- 大语言模型的局限：幻觉、上下文长度限制、时效性不足、隐私与安全风险。

### 2.2 阶段产出

- 能够用自己的话解释大语言模型的基本工作方式。
- 能够举出 3 到 5 个大语言模型应用场景。
- 能够区分“模型能力”和“应用系统能力”。

### 2.3 建议学习时间

建议用 2 到 3 天完成基础认知学习，并通过实际使用大模型产品形成直观理解。

---

## 3. 阶段二：数学与机器学习基础

### 3.1 学习重点

大语言模型背后依赖深度学习理论，但入门阶段不需要一次性掌握全部数学推导。建议优先学习能够帮助理解模型训练和推理过程的基础知识。

需要掌握的内容：

- 线性代数基础：向量、矩阵、矩阵乘法、向量相似度。
- 概率统计基础：概率分布、条件概率、最大似然估计、交叉熵。
- 机器学习基础：训练集、验证集、测试集、过拟合、欠拟合、损失函数、梯度下降。
- 神经网络基础：神经元、激活函数、前向传播、反向传播、优化器。
- 表示学习基础：词向量、Embedding、语义相似度。

### 3.2 阶段产出

- 能够理解模型为什么需要训练数据。
- 能够解释损失函数和梯度下降的基本作用。
- 能够理解 Embedding 将文本映射为向量表示的意义。

### 3.3 建议学习时间

建议用 1 到 2 周完成核心概念学习，不必追求复杂公式推导，重点是为后续理解 Transformer 和 RAG 打基础。

---

## 4. 阶段三：NLP 与 Transformer 核心技术

### 4.1 学习重点

Transformer 是现代大语言模型的核心架构。学习时建议先理解整体结构，再逐步拆解注意力机制、位置编码和解码生成过程。

需要掌握的内容：

- 传统 NLP 与深度学习 NLP 的区别。
- Tokenization：字符、词、子词切分方式。
- Word2Vec、BERT、GPT 等模型的发展脉络。
- Transformer 基本结构：Encoder、Decoder、Self-Attention、Feed Forward、LayerNorm。
- 注意力机制：Query、Key、Value 的基本含义。
- 自回归生成：模型如何一个 Token 一个 Token 地生成文本。
- 上下文窗口与长文本处理的限制。

### 4.2 阶段产出

- 能够画出 Transformer 的基本结构图。
- 能够解释 Self-Attention 为什么适合处理文本上下文关系。
- 能够说明 GPT 类模型为什么适合生成任务。

### 4.3 建议学习时间

建议用 1 到 2 周完成，配合图解文章、动画演示和简单代码示例学习效果更好。

---

## 5. 阶段四：大模型使用与提示词工程

### 5.1 学习重点

对于应用开发者来说，提示词工程是最快能够产生实际效果的能力。它决定了模型能否准确理解任务、输出稳定结果，并与业务流程结合。

需要掌握的内容：

- Prompt 的基本结构：角色、任务、背景、约束、示例、输出格式。
- Zero-shot、Few-shot、Chain-of-Thought 等提示方式。
- 结构化输出：JSON、Markdown、表格、固定字段。
- 提示词调优：明确目标、减少歧义、补充示例、约束边界。
- 常见任务模板：总结、分类、问答、翻译、代码生成、数据抽取。
- 提示词安全：避免提示注入、敏感信息泄露和越权回答。

### 5.2 示例提示词

```text
你是一名大语言模型学习导师。请根据学习者基础为其制定 4 周学习计划。
要求：
1. 按周列出学习目标。
2. 每周包含理论学习、实践任务和验收标准。
3. 输出为 Markdown 表格。
4. 内容适合零基础本科生理解。
```

### 5.3 阶段产出

- 能够编写清晰、稳定、可复用的提示词。
- 能够让模型按照指定格式输出内容。
- 能够设计适合演示场景的 Prompt 模板。

### 5.4 建议学习时间

建议用 3 到 5 天完成，并通过多个任务反复练习。

---

## 6. 阶段五：API 调用与应用开发

### 6.1 学习重点

掌握 API 调用后，就可以将大语言模型能力接入 Web 应用、管理系统、知识库系统或自动化工具中。

需要掌握的内容：

- 大模型 API 的基本调用方式。
- 请求参数：model、messages、temperature、max_tokens、stream 等。
- 多轮对话上下文管理。
- 流式输出与前端打字机效果。
- 错误处理、超时重试、限流控制。
- 用户输入过滤与敏感内容处理。
- 后端封装：统一模型服务接口，便于切换不同模型供应商。

### 6.2 推荐实践任务

- 实现一个简单的 AI 聊天页面。
- 实现一个“文档总结助手”。
- 实现一个“学习路线生成助手”。
- 将大模型接口封装为后端服务，前端通过接口调用。

### 6.3 阶段产出

- 能够完成一次完整的大模型 API 调用。
- 能够开发一个具备基础交互能力的 AI 应用。
- 能够说明 temperature、上下文和流式响应对结果的影响。

### 6.4 建议学习时间

建议用 1 周完成，重点放在接口调用、对话状态管理和前后端联调。

---

## 7. 阶段六：RAG 检索增强生成

### 7.1 学习重点

RAG 是大语言模型落地知识库问答、企业文档助手和课程答疑系统时非常常用的方案。它通过“先检索，再生成”的方式，让模型回答更加贴近私有知识库内容。

需要掌握的内容：

- RAG 的基本流程：文档上传、文本切分、向量化、向量检索、上下文拼接、模型生成。
- 文档解析：Markdown、PDF、Word、网页文本等。
- Chunk 切分策略：按长度、按标题、按语义段落。
- Embedding 模型与向量数据库。
- 相似度检索：余弦相似度、TopK 召回。
- Prompt 拼接：如何把检索结果作为上下文传给模型。
- 评估指标：命中率、相关性、事实一致性、回答完整性。

### 7.2 RAG 基本流程

```text
用户问题
  ↓
问题向量化
  ↓
向量数据库检索相关文档片段
  ↓
将检索片段与问题组合成 Prompt
  ↓
调用大语言模型生成答案
  ↓
返回答案与引用来源
```

### 7.3 阶段产出

- 能够解释 RAG 与普通聊天机器人的区别。
- 能够设计一个文档知识库问答系统的基本架构。
- 能够完成一个基于本地文档的问答 Demo。

### 7.4 建议学习时间

建议用 1 到 2 周完成。对于演示项目，可以优先实现 Markdown 文档问答，再扩展 PDF 和 Word 文档解析。

---

## 8. 阶段七：模型微调与私有化部署

### 8.1 学习重点

当提示词和 RAG 无法满足特定任务时，可以进一步学习模型微调。微调适合让模型学习固定格式、领域表达方式或特定任务模式。

需要掌握的内容：

- 预训练、指令微调、监督微调的区别。
- LoRA、QLoRA 等轻量化微调方法。
- 数据集构建：指令、输入、输出三元组。
- 数据清洗与质量控制。
- 训练参数：学习率、batch size、epoch、上下文长度。
- 推理部署：GPU、量化、显存占用、并发性能。
- 开源模型部署工具：Ollama、vLLM、LM Studio、Text Generation Inference 等。

### 8.2 阶段产出

- 能够判断什么时候需要微调，什么时候使用 Prompt 或 RAG 即可。
- 能够理解 LoRA 微调的基本思路。
- 能够本地运行一个开源大语言模型。

### 8.3 建议学习时间

建议用 2 到 3 周完成。该阶段对硬件和工程能力要求较高，演示时可以选择轻量开源模型进行展示。

---

## 9. 阶段八：智能体与工具调用

### 9.1 学习重点

智能体是大语言模型应用的重要方向。它让模型不仅能回答问题，还能调用工具、执行任务、规划步骤，并与外部系统协作。

需要掌握的内容：

- Agent 的基本概念：感知、规划、行动、反馈。
- Function Calling / Tool Calling 工具调用机制。
- ReAct 思想：推理与行动结合。
- 常见工具：搜索、数据库查询、代码执行、文件读写、接口调用。
- 多智能体协作：任务分解、角色分工、结果汇总。
- 智能体安全：权限控制、操作确认、日志审计。

### 9.2 推荐实践任务

- 开发一个“课程学习助手”，根据用户目标生成学习计划。
- 开发一个“代码解释助手”，读取代码文件并给出说明。
- 开发一个“知识库运维助手”，根据用户指令查询文档索引状态。

### 9.3 阶段产出

- 能够解释智能体与普通聊天应用的区别。
- 能够设计一个具备工具调用能力的 AI 助手。
- 能够认识到智能体应用中的权限与安全边界。

### 9.4 建议学习时间

建议用 1 到 2 周完成，重点放在工具调用流程和任务编排思路。

## 10. 综合项目建议

为了便于明天演示，可以选择一个较完整但范围可控的项目作为展示案例。

### 项目名称：大语言模型学习路线生成与知识问答助手

### 项目目标

构建一个面向学生的大语言模型学习助手，支持用户输入学习目标、基础水平和计划周期，系统自动生成学习路线，并支持基于课程文档进行知识问答。

### 核心功能

- 学习路线生成：根据用户基础生成分阶段学习计划。
- 知识库问答：根据上传文档回答学习问题。
- 文档总结：对课程资料进行摘要和重点提取。
- Prompt 模板管理：保存常用提示词模板。
- 学习成果验收：根据阶段目标生成测验题或实践任务。

### 技术结构

```text
前端页面
  ↓
后端业务接口
  ↓
大模型服务封装
  ↓
Prompt 模板 / RAG 检索 / 对话上下文
  ↓
模型 API 或本地开源模型
```

### 演示流程建议

1. 展示学习路线文档，说明学习阶段和目标。
2. 输入“零基础，4 周入门大语言模型应用开发”，生成学习计划。
3. 上传或选择一份课程文档，提问“RAG 的核心流程是什么”。
4. 展示系统返回答案和引用内容。
5. 总结项目价值：降低学习门槛，提高资料利用率，辅助课程答疑。

## 13. 常见问题

### 13.1 是否必须先学完数学才能学大语言模型？

不需要。应用开发方向可以先从 Prompt、API 和 RAG 入手，后续再补充数学和模型原理。研究算法方向则需要更系统地学习数学和深度学习。

### 13.2 Prompt、RAG 和微调应该如何选择？

- 如果只是优化回答风格和输出格式，优先使用 Prompt。
- 如果需要回答私有文档或企业知识，优先使用 RAG。
- 如果需要模型长期掌握特定任务格式或领域表达方式，再考虑微调。

### 13.3 大模型应用开发最重要的能力是什么？

最重要的是将模型能力与真实业务流程结合，包括问题拆解、提示词设计、数据处理、接口封装、结果评估和安全控制。

## 14. 总结

大语言模型技术学习可以按照“基础认知、核心原理、应用开发、RAG 知识库、微调部署、智能体应用”的路线逐步推进。对于明天的演示，建议重点突出 Prompt、API 调用和 RAG 知识库三个方向，因为它们最容易展示实际效果，也最贴近当前大模型应用落地场景。

只要能够完成一个“学习路线生成 + 文档问答”的小项目，就可以较好地体现大语言模型在学习辅助、知识管理和智能问答中的实际价值。
